# T20. Configuration, fonts and themes

Status: not started

A config file loaded and validated in the core, with font, colour scheme, scrollback and key binding settings, live reload, and a settings view on each platform. Done when a change applies without restart.

Execution plan (split to fit the budget):
- T20.1. `scull-config` model: `Config` TOML types (font family and size, colour scheme with overrides, scrollback), defaults, built-in schemes, load with a size cap and `deny_unknown_fields`, errors that name the file, JSON Schema committed to `docs/config.schema.json` with a stale-schema test. Verify: unit tests for parsing, defaults, every validation error and caps.
- T20.2. Key bindings in `scull-config`: `[[keybind]]` chord parsing over `scull_input::{Key, Modifiers}`, an action enum, default bindings merged with the user's, caps and duplicate checks. Verify: parsing and rejection tests.
- T20.3. Editing and live reload in `scull-config`: `toml_edit` setter that validates before it writes and replaces the file atomically; `notify` watcher on the parent directory feeding a store with a generation counter and the last error (a bad edit keeps the last good settings). Verify: tests that edit a temp file and see the generation and values change, and a broken edit keep the old settings. The watcher must not drop a reload when the config directory is flooded with events (from T30): every write that changes the watched file produces a reload, or a coalesced reload that includes it. A stress test floods the directory and fails if a meaningful write is lost.
- T20.4. C ABI in `scull-ffi`: `tt_config` handle (`new`, `poll` into a sized `tt_config_view`, `set`, `free`) behind the wakeup callback only; bump the ABI minor; the bindings generator; extend the C test under ASan and TSan. Verify: Kotlin/Native tests, the C ABI sanitizer test, `just bindings-check`.
- T20.5. macOS: new `ScullKit/Config.swift` wrapper and `Palette`/`TerminalView` reading it (font, colours, key bindings, scrollback for new terminals); live reload through the wakeup. Verify: the macOS app build, `swift test` in `macos/`, and the `-ScullSnapshot` PNG before and after editing the file while the app runs.
- T20.6. macOS settings view: new SwiftUI `Settings` scene in new files (family, size, scheme, scrollback) that writes through `tt_config_set`. Verify: the macOS app build, a snapshot after a change made through the view.
- T20.7. Windows settings view, reusing T20.1 to T20.4 unchanged. T17 delivers the WinUI app; this slice is split to fit the budget:
  - T20.7.1. `windows/Scull.Core/Config.cs`: `Config` owns one `tt_config` through `NativeHandle` and `Lease` (wakeup through a `GCHandle` and an `[UnmanagedCallersOnly]` trampoline, as `Terminal.Spawn` does it). `Open` checks the ABI, `TryPoll` copies the sized view into an immutable `ConfigSettings` (no pointers outlive the poll), `Set` writes through `tt_config_set`, `Dispose` frees; non-OK statuses are `ScullException`s. Verify: MSTest `ConfigTests` in `windows/Scull.Core.Tests` against the real library on every runner (defaults and path, a file read at open, `Set` validating and writing while keeping the rest of the file, `Set` refusing bad input with the file untouched, a live edit waking the host and bumping the generation, a broken edit keeping the last good values with an error naming the file, no wakeup after `Dispose`, use after `Dispose`); `./gradlew check`, `dotnet test windows/Scull.slnx`, `dotnet build` with warnings as errors.
  - T20.7.2. Apply font, colours, key bindings and scrollback in `Scull.App` and `Scull.Render` from `Config`, live through the wakeup marshalled to the UI thread (scrollback for new terminals only). Verify: renderer tests on a Windows runner and a run of the app while the file is edited.
    Execution plan: (1) `Scull.Core/ConfigBindings.cs`, plain C#: the configured action for a key (`WindowsKeys.Map`) and the shortcut modifiers held, matched exactly as `TerminalView.runBinding` does; and `FontZoom`, the configured family and size plus the larger/smaller/reset steps clamped to 4–200 and reset when the file changes the font. (2) `Scull.Render`: `Palette` from `ConfigSettings` (foreground, background, cursor and the sixteen ANSI colours over xterm's cube and greys, as `Palette+Config.swift` does); `Renderer.Palette` settable, which rebuilds every row; `Renderer.SetFont` replacing the faces, shaper and atlas while the pipeline stays. A configured family that is not installed falls back to Cascadia Mono, then Consolas. (3) `Scull.App`: `App` opens one `Config` at launch (a failed open keeps the built-in defaults) and exposes it for the settings window (T20.7.3); its wakeup posts to the UI thread's `DispatcherQueue`, which polls and tells every window. A window applies the palette and font to its panes, spawns new terminals with the configured scrollback, matches bindings before keys reach the terminal (paste, font larger/smaller/reset, scroll page/top/bottom) after the pane commands, and shows a config error in an `InfoBar` while the last good settings stay. Edits to `TerminalWindow` and `TerminalPane` stay small (T18.3 works there). (4) Tests: binding matching, font steps and the palette on every runner; on WARP (Windows), a new palette's background and a new font's cell size and glyphs after `SetFont`. Verify: `./gradlew check`, `dotnet test windows/Scull.slnx`, warnings as errors, `dotnet build` of the WinUI app on the Windows CI runner.
  - T20.7.3. WinUI settings window (family, size, scheme, scrollback) writing through `Config.Set`. Verify: `dotnet build` of the WinUI app on a Windows runner and a screenshot after a change made through the window.
    Execution plan: (1) `Scull.Core/SettingsForm.cs`, pure and tested on every runner: the keys (`font.family`, `font.size`, `colors.scheme`, `scrollback`), the built-in scheme list (macOS `SettingsView.swift`'s: scull-dark, scull-light, solarized-dark), the bounds the core enforces (font size 4 to 200 in steps of 0.5, scrollback 0 to 1,000,000), the validation of typed values into `SettingChange(Key, Value)` with a message for each refusal, and `Write(Config, SettingChange)` that returns the core's message when `Set` throws `Invalid` or `Io`; (2) `Scull.App/SettingsWindow.cs`, code only: an editable font ComboBox (empty is the system monospace), a NumberBox for the size, a ComboBox for the scheme, a NumberBox for scrollback with the note that it applies to terminals opened afterwards, the refusal or the file's own `Error` in red, a Show config file button; it takes a `Config`, shows `Config.Settings`, writes each change through `SettingsForm.Write`, and `Refresh(ConfigSettings)` moves the controls when the App polls (the App owns and polls the `Config`, T20.7.2); (3) the hook: `PaneCommand.OpenSettings` on Ctrl+, and `App.OpenSettings()`, which does nothing until T20.7.2 assigns `App.Config`. Verify: `./gradlew check`, `dotnet test windows/Scull.slnx`, CI `dotnet build` of the WinUI app; how it looks needs a human.

Acceptance:
- [ ] The work described above is implemented in Kotlin/Native (platform UI stays Swift/C# where this task says so).
- [ ] Tests and the `./gradlew check` gate (plus the platform tests this task names) pass.
