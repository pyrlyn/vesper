# T17. Windows app and renderer

Status: not started

A C# WinUI 3 shell with a `SwapChainPanel` surface, a D3D11 renderer and a DirectWrite atlas. The first step evaluates the interop library that gives C# access to Direct3D and DirectWrite (maintenance, coverage, allocation cost per frame) and records the pick in `toolchain.md`; the research evaluated none. Done when a shell is usable and the T3 benchmark runs on Windows.

Execution plan (split to fit the budget). C# lives in `windows/`; the core is reached only through the committed C# P/Invoke bindings generated from `scull.h`.

- T17.1 Interop pick and the managed core: compare Vortice.Windows, TerraFX.Interop.Windows, Microsoft.Windows.CsWin32 and Silk.NET for Direct3D 11, DXGI, DirectWrite, TSF and UIA (maintenance from NuGet and GitHub releases, coverage, per-frame allocations, AOT and trimming, licence), recorded in `research.md` with sources and the pick in `toolchain.md`. `NativeMethods.g.cs` generated from `scull-ffi/include/scull.h` (moved here from T10, so the bindings are proven on the real host): the generator picked and pinned in `toolchain.md`, a `just bindings` recipe, the output committed and diff-checked in CI. `windows/Scull.Core`, a platform-neutral class library over `NativeMethods.g.cs`: `Terminal` (create, feed, resize, events and bell, frame update and view, read text), `SafeHandle` ownership so each handle is freed once, the ABI version checked at start-up, status codes mapped to exceptions, poisoning tracked as `TerminalSession.swift` does. `windows/Scull.Core.Tests` loads the real core library and covers each of those. `dotnet test windows/Scull.slnx`, and a CI job on Windows and macOS. Verify: `./gradlew check`, `dotnet test windows/Scull.slnx`, `dotnet build` with warnings as errors.
- T17.2 Renderer library, testable headless: `windows/Scull.Render` (`net10.0-windows`, no WinUI types) over CsWin32 (`NativeMethods.txt` lists only what it uses, `allowMarshaling: false`). A D3D11 device, hardware or WARP when asked; DirectWrite rasterises glyphs into a shelf-packed BGRA atlas texture with eviction, growth and a generation, as grayscale coverage and as colour glyphs (COLR layers composited on the CPU); instanced quads for cell backgrounds, glyphs, underline and strike decorations and the cursor, in per-row instance slots that a scroll only remaps and dirty rows refill, drawn from a `Scull.Core` frame view into any render target view (a swap chain's back buffer in T17.3, an offscreen texture in the tests). HLSL compiled at start-up with `D3DCompile`. No allocation per frame in the steady state (struct COM pointers, pooled instance arrays). Glyphs come from the cell's code point through the face and a short fallback list; not in this slice: shaping with ligatures and `IDWriteFontFallback`, combining marks, box drawing and Powerline sprites and image placements (T17.5). `windows/Scull.Render.Tests` (MSTest): a real `Scull.Core.Terminal` fed text and colours, rendered on WARP into an offscreen texture and read back (background colours at known cells, coverage where text is and none where blank, the cursor block, one atlas entry for a repeated glyph), and the packer's growth and eviction as pure logic, which also runs on macOS and Linux. The solution builds everywhere (`EnableWindowsTargeting`); the Direct3D tests run only on Windows and are skipped elsewhere. Verify: `./gradlew check`, `dotnet test windows/Scull.slnx` locally and on the three CI runners, warnings as errors.
- T17.3 WinUI 3 shell: an unpackaged app with a `SwapChainPanel` (one swap chain per window) drawn by `Scull.Render`; `tt_term_spawn` with the wakeup posted to the dispatcher queue; keys, text, mouse, wheel, paste and focus mapped to the exports; `resize_begin`/`resize` on a drag.
  Split at claim time to fit the 500-line budget:
  - T17.3.1 Window, swap chain and child. `Scull.Core`: `Terminal.Spawn` (program, arguments, directory, environment; the wakeup through a `GCHandle` and an `[UnmanagedCallersOnly]` trampoline, freed with the terminal handle so no wakeup outlives it). `Scull.Render`: `SwapChainTarget`, a `RenderTarget` over `IDXGIFactory2.CreateSwapChainForComposition` (flip sequential, stretch, BGRA), with `Resize` (`ResizeBuffers`), `Present` and the inverse composition scale (`IDXGISwapChain2.SetMatrixTransform`) so one buffer pixel is one screen pixel. `windows/Scull.App`: an unpackaged, self-contained WinUI 3 app (latest stable Microsoft.WindowsAppSDK, code-only, no XAML pages) whose window holds one `SwapChainPanel`; `ISwapChainPanelNative.SetSwapChain` through a raw vtable call (IID from the Windows App SDK IDL); the default shell spawned with `TERM`/`COLORTERM` as on macOS; the wakeup posts one cached handler to the `DispatcherQueue`, which drains events, updates, absorbs and renders; a size change calls `resize_begin` once and `resize` after a short quiet period (WinUI 3 has no live-resize events); a DPI change (`XamlRoot.Changed`, `CompositionScaleChanged`) rebuilds the renderer at the new pixel size; the child's exit closes the window, a poisoned terminal shows a notice. Scull.App is Windows only (the XAML tooling runs only there): it is not in `Scull.slnx`, `dotnet build` of the WinUI app builds it with warnings as errors, and the CI step runs it on the Windows runner. Tests (all runners where the OS allows): spawn with output, exit code and the wakeup; a resize the child sees (Unix); the swap chain target on WARP (Windows).
  - T17.3.2 Input. `Scull.Core`: `Key`, `Text`, `Paste`, `Focus`, `Mouse` and `ScrollDisplay` wrappers (false when the child is not reading or gone), the public key, modifier and mouse vocabulary, and the pure Windows mapping: scan code and virtual key to the core's key, the `KeyDown`/`CharacterReceived` pairing (a text key waits for its character; Control, Alt and non-text keys are sent at once and their character dropped; AltGr's character keeps Ctrl+Alt as consumed; surrogate pairs joined), pixel to cell, and wheel deltas to steps. `Scull.App` wires the panel's key, character, pointer, wheel and focus events, Ctrl+Shift+V and Shift+Insert to paste. - T17.9 Core terminal events in the Windows shell: `EventKind` knew only the bell and the child's exit, so titles, the working directory and OSC 52 were dropped. As `TerminalSession.drainEvents` does on macOS: a title (not an icon-only one) becomes the tab's header and, for the selected tab, the window's title; the working directory (OSC 7, a local `file://` URL) is kept on the pane and nothing more (macOS only stores it too); an OSC 52 write puts its UTF-8 text on the clipboard (other bytes are dropped); an OSC 52 read is denied, because it would hand the user's clipboard to whatever the shell runs.
  Execution plan: (1) `Scull.Core/Terminal.cs`: `EventKind` gains `Title`, `WorkingDirectory`, `ClipboardRead`, `ClipboardWrite` (and the other ABI kinds, which the shell ignores); `TerminalEvent` carries `Id`, `Detail` and `Text` (bytes read through `tt_term_event_text` right after the poll, since only the last polled event's text is readable, grown on `TT_FULL`); `Terminal.ClipboardDeny(id)`. (2) `Scull.Core/EventPolicy.cs`, pure: `TitleOf` (icon-only titles skipped), `PathOfUrl` (local `file://` URL to a path, the host must be empty or `localhost`), `ClipboardText` (strict UTF-8 or null). (3) `Scull.App`: `TerminalPane.Exited()` becomes `Drain()` returning the child's exit and keeping `Title`, `WorkingDirectory`, with `ClipboardWritten` and denied reads handled there; `TerminalWindow` sets the tab header (fallback `Terminal N`) and the window title (fallback `Scull`) and writes the clipboard through `DataPackage`. (4) Tests: `EventTests` feeds a real `Terminal` OSC 0, 1, 2, 7 and 52 write and read sequences and reads the events; `EventPolicyTests` for the pure helpers. Verify: `./gradlew check`, `dotnet test windows/Scull.slnx`, CI incl. `dotnet build` of the WinUI app. Not touched: the pointer handlers (T17.8) and `Scull.Render` (T17.10).
